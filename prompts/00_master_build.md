# 00 — Master build prompt

Load this first in every session. It holds what must always hold, how work is gated and who owns what. It holds no design: the simulation, the data model and every domain number live in the files named in section 0.

## Working principles (mandatory)

Principles: see `prompts/PRINCIPLES.md` (definitions, stage table, rails, brief header). The stage combination is set per session by its stage table. Always KISS, AHA, SRP, Small Batches. The rails cited below are PRINCIPLES.md section 6.

## 0. Source of truth

Highest first: `docs/adr/` (decisions) → `docs/design/*` (`simulation_spec.md`, `data_model.md`, `data_dictionary.yaml` once S2 creates it) → `schemas/*` (S1) → `prompts/*`. A prompt carries process, gates, ownership and pointers; it never restates design content. If a prompt disagrees with a design file, the design wins: do not follow the prompt, record the conflict under "Open questions" in `docs/progress.md` and tell the orchestrator, who fixes the prompt. If a design file disagrees with an `Accepted` ADR, the ADR wins.

Domain numbers live in `docs/research/assumptions.yaml` (`A###`) and `docs/research/sources.yaml` (`S###`); every value the design uses cites an `A###` id in the spec, so values come from `docs/research/assumptions.yaml` via the ids cited in the spec. A prompt holds only test-only numbers (fixture times, analytic targets) and says so where it does.

## 1. Mission and non-goals

Build a public, browser-runnable simulator: one synthetic truth run, recorded under several data architectures, showing what each one can reconstruct afterwards. Purpose, layers, profiles, flags, experiments, scenarios and metrics: `docs/design/simulation_spec.md` §1 to §9. Non-goals: spec §10 (no prediction of a real lab, no compliance claims, no real data, no single summary score), and never "making C win by construction": orderings must emerge from mechanisms.

The portfolio centre is not the screen. It is: the single-sample failure trace, the canonical DDL, three core SQL queries, the analyzer-CSV-to-canonical mapping and the source ledger.

## 2. Invariants (every session, every file)

1. **Truth vs recorded.** The engine emits a `truth_log` and an `observable_events` stream (spec §3). Recorders (L4) consume only `observable_events`. Hidden fields are annotated `"x-visibility": "hidden"` in `schemas/`. Test: perturb hidden-only fields; recorder output is byte-identical. Only the metrics evaluator reads the error answer key; L5 never reads truth, except the oracle arm of experiment 2.
2. **Determinism.** Same `(scenario, seed, engine_version)` gives a byte-identical event log. Integer seconds for all event times. Randomness only from a keyed integer PRNG with one canonical key tuple `(run_seed, physical_sample_id, analyte, attempt, purpose)`, mapped to a stream seed by splitmix64 over BigInt, synchronously (details in `10_S1_engine.md`, Step 1). A rerun or an added sample must not change any other sample's draws. `Math.random`, `Date.now()` and `new Date()` are banned in `engine/src/**` (lint plus the grep in `scripts/check_all.sh`). Seeds are neutral values, never date-shaped.
3. **Source ids.** Every number shown publicly, and every parameter default in a profile or scenario, carries an `S###` or `A###` id that exists in the ledgers. Code reads values from profile/scenario JSON; no domain constant is hard-coded. Grade `A` values are labelled assumptions. Public numbers use only `main-reread` sources, and an `A###` is followed to its `S###` sources. `check_docs.py` enforces ids.
4. **ADRs are Proposed only.** Use the `adr-new` skill. Never write a decider's note, never set `Accepted`.
5. **Author-owned files are review-only:** everything in `.claude/user_owned.txt`. AI writes specs, fixtures, acceptance tests and reviews; never the implementation. Do not route around the edit guard with `bash`, `cp`, `sed` or heredocs.
6. **One contract.** `schemas/*.schema.json` is the single source for events, traces, scenarios and profiles. TS types are generated, Python validates with `jsonschema`. Every export and shareable URL carries `schema_version`, `engine_version`, `seed`.
7. **Generic engine.** No branch on a profile id, scenario id or architecture id inside the engine core. Exactly eight feature flags (spec §5); a ninth needs a Proposed ADR.
8. **No false precision.** Stochastic comparisons are reported across at least 20 seeds with intervals and are never gates; a gate is structural (a forced-error fixture with a hand-typed expected outcome). Never require a stochastic ordering ("C must win", "recall higher on every seed"). Warn on extrapolation outside a source's range; make no numeric claim for a stage that has no result yet.
9. **Golden files are never regenerated by a script or by a test.** Changing one needs the author's approval recorded in `docs/progress.md`.
10. **Synthetic only, headless only, no publishing** (rails 1, 4, 5).
11. **Names.** Canonical names come from `docs/design/data_model.md` (`unit`/`unit_id`, `batch_id`, `sample_id`, `aliquot_id`, `lineage_edge`, `method_id`, `unit_ucum`, `state`); event and state names from spec §2 and data_model §6. A new name needs a design change first.
12. **Raw device layer.** Rules R1 to R3 of `docs/adr/0014-equipment-output-adapters-from-public-docs.md`, checked at `20_S2_capture_metrics.md` Step 8; design in spec §2.4 and data_model §16.

## 3. Terms every brief uses (mirror of the design; the design wins)

- Time fields, `hold_time`, `turnaround` and the as-of rule are defined in `docs/design/data_model.md` §5 and nowhere else. Columns: `run.started_at` (written `run_started_at` in formulas), `run.ended_at` (the instant of `measured_at`), `historian_value.ts` (validity time) and `historian_value.ingested_at` (transaction time). Recorded clocks may be skewed in L4.
- The flags `two_clocks` and `write_time_keys` are independent (spec §5); every test states the expected outcome per flag.
- Utilisation is always stated per staffed window (scenario setting, default 10 h) and per 24 h, and says whether setup time counts.

Scenario-to-session assignment: spec §7. Prompts `30_*`, `40_*`, `50_*` are written at the start of their session, not before.

**Budgets (measured, not estimated).** Default scenario, one seed: at most 1 s in a Web Worker (S1 checks a Node median of 5 runs as a proxy; S3 checks the Worker). Infographic at most 150 KB gzip; lab first load at most 300 KB gzip (`gzip -c <file> | wc -c`). A breach is a major finding.

## 5. Verification ladder

Five rungs (spec §9): invariants, M/M/c-only check, hand-calculated fixtures, SimPy trace-driven parity, scenario sanity. Test details and tolerances live in `10_S1_engine.md`. Scenario sanity states relations (sign, ordering, structural zero), never magnitudes.

## 6. Ownership and commits

Layout (matches `CLAUDE.md`): engine in `engine/` with tests beside it (`engine/tests/`); UI in `src/` (S3); shared fixtures in `tests/fixtures/`, goldens in `tests/golden/`; acceptance tests for the author's code in `tests/user_track/`; root `package.json` drives `npm run check`.

AI-owned: `engine/`, `src/`, `tests/`, `schemas/`, `scenarios/`, `scripts/`, `docs/design/`, `docs/progress.md`, `prompts/`. Ledgers (`docs/research/*.yaml`) are written by the research role; engine code only reads them. Author-owned: `sql/`, `reference/`, ADR decider notes, `Accepted` status, commits of Accepted ADRs, `git push`, visibility change.

**The orchestrator commits; executors never do.** Tidy First: the orchestrator lands structure-only changes and behaviour changes as separate commits, each made with `git add <paths>`, so an executor's report lists the two path sets apart.

## 7. Definition of done (every session)

- [ ] Every new behaviour has a test seen red, then green; pasted evidence in the report.
- [ ] `uv run pytest -q` and `uv run --frozen python scripts/check_docs.py --all` both pass. From S1 on, `npm run check` passes too.
- [ ] `bash scripts/check_all.sh --manual` passes (it runs the same gate as the Stop hook without needing a dirty marker).
- [ ] Python dependencies only through `uv`; Node packages with exact versions; every browser closed.
- [ ] Only files in the brief's allowed paths changed: `git status --short -uall` (shows untracked files; plain `git diff` does not).
- [ ] `docs/progress.md` has a new entry: date, what changed, evidence, Parked, Open questions.
- [ ] Report is at most 300 words: files with line counts, commands with output tails, deviations, blocked items.
